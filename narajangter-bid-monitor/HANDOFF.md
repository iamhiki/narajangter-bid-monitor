## 3. 시스템이 하는 일 (실행 흐름)

`.github/workflows/weekly-bid-report.yml` — 매주 월요일 07:00 KST(일요일 22:00 UTC)
자동 실행, `workflow_dispatch`로 수동 실행도 가능(dry_run 옵션 있음).

`npm run report` (`src/index.ts`)가 하는 일, 순서대로:

1. **조회**: data.go.kr의 입찰공고정보서비스(본공고) + 사전규격정보서비스를
   물품/용역/공사 3종 × 2개 API = 총 6개 오퍼레이션으로 최근 7일(`LOOKBACK_DAYS`)치
   조회
2. **1차 필터 (제외 키워드)**: 제목에 `excludeKeywords` 중 하나라도 있으면 무조건 제외
   (코드/키워드 매칭 여부와 무관) — `src/matching/keywordMatcher.ts`의
   `matchExcludeKeyword`
3. **2차 필터 (최소 예산)**: `budgetAmount`가 있고 `minBudgetAmount`(현재 1억원) 미만이면
   제외. 예산 정보가 없는 공고는 판단 불가로 통과시킴
4. **3차 필터 (코드/키워드 매칭)** — `src/matching/matchEngine.ts`의 `evaluateNotice`:
   - **세부품명번호(물품, `productCodes`)**: 정확 일치. 정밀도가 높아서 **단독으로도
     포함**됩니다.
   - **업종코드(용역/공사, `industryCodes`)**: "투찰가능업종명" 텍스트 부분일치라
     정밀도가 낮음(무관한 공사도 "실내건축공사업" 등을 참가가능업종에 폭넓게 나열하는
     경우가 많음) → **제목 키워드가 함께 있을 때만** 인정, 업종코드 단독매칭은 제외됨
   - **제목 키워드(`keywords`)**: 제목+품목명에 포함되면 매칭. 단독으로도 포함됨
   - 코드+키워드가 둘 다 매칭되면 "강력추천", 키워드만(또는 물품코드만) 매칭되면
     "참고용"
   - 키워드/제외키워드 비교 시 공백은 자동 무시("운영 용역" == "운영용역")
5. **4차 필터 (자격조건, 본공고만)** — `src/matching/qualificationFilter.ts` /
   `applyQualificationFilter.ts`: data.go.kr의 면허제한정보조회 API로 공고별 참가자격
   제한그룹을 가져와서, 지일이 `config/held-qualifications.json`에 등록된 자격으로
   충족 못하는 그룹이 **2개 이상**이면 제외 (1개까지는 통과, 그룹 내 하나만 보유해도
   그 그룹은 충족). 조회 실패/정보없음이면 걸러내지 않고 통과(fail-open). 사전규격은
   대응 API가 없어 이 필터 대상이 아님
   - **지역제한 (2026-10-14 추가)**: 참가가능지역정보조회 API(`src/api/regionLimitApi.ts`)로
     공고별 참가 가능 지역을 받아, 본점 소재지(`config/company-profile.json`의
     `headquartersRegion`)와 같은 시·도가 하나도 없으면 제외 (`src/matching/regionFilter.ts`).
     시·군까지 좁힌 공고(예: 강원특별자치도 횡성군)는 남긴다. 조회 실패 시 통과(fail-open).
   - 설계용역(용역 + 제목에 '설계')은 최소 예산 기준을 보지 않는다
     (`keywords.json`의 `minBudgetExemption`). 수의계약 제외는 그대로.
6. **리포트 생성 + 저장** (`output/` 폴더, GitHub Actions 아티팩트로도 백업)
7. **이메일 발송** (`config/recipients.json`의 전체 수신자에게), 실패 시 실패 알림
   메일 별도 발송

## 6. 운영 방법

- **자동 실행**: 매주 월요일 07:00 KST. 성공하면 이메일 발송, 실패하면 실패 알림
  메일 발송 (recipients 전원에게).
- **수동 실행**: GitHub 저장소 → Actions → "나라장터 입찰 모니터링 주간 리포트" →
  Run workflow. `dry_run: true`로 하면 이메일 안 가고 `output/`에 리포트만 생성 +
  아티팩트로 다운로드 가능.
- **로컬 dry-run**: `.env`에 실제 API 키가 있으면 `npm run report:dry-run`으로
  로컬에서도 확인 가능 (단, 이 세션/일부 sandbox 네트워크 정책상 `apis.data.go.kr`
  접속이 막혀 있을 수 있음 — GitHub Actions에서 실행하는 게 확실함).
- **결과 확인**: GitHub Actions 실행 로그의 `"매칭 결과"` 로그 라인에
  `{본공고, 사전규격, 실패한조회}` 건수가 남고, `"이메일 발송 완료"` 라인에
  실제 수신자 목록과 총 매칭 건수가 남음. 실제 공고 제목까지 보려면 실행의
  아티팩트(`bid-report-<run_id>`)를 다운로드해서 `output/*.html`을 열면 됨.

## 8. 알려진 한계 / 트러블슈팅

- **제목 기반 매칭의 한계**: data.go.kr API는 공고 "제목"과 일부 메타데이터만
  주고, 상세 "과업내용"은 첨부파일(HWP/PDF)로만 제공돼서 API로 못 가져옴. 즉
  키워드 매칭은 제목+품목명만 봄 — 과업내용에만 단서가 있는 공고는 못 잡을 수
  있음. **완전 자동화에만 의존하지 말고 나라장터를 가끔 직접 훑어보는 걸 권장.**
- **업종코드 매칭 정밀도**: "투찰가능업종명" 텍스트에 여러 업종이 나열되는데,
  API가 정형 코드 목록이 아니라 텍스트 한 덩어리로만 줘서 부분일치로 판단함.
  이 때문에 무관한 공사도 걸릴 위험이 있어서 (3번 문단 참고) 업종코드 단독
  매칭은 이제 결과에 안 씀.
- **data.go.kr 연결 불안정**: 과거 여러 차례 타임아웃/연결실패("fetch failed")
  경험 있음 — 재시도(`API_MAX_RETRIES`, 기본 5회)와 넉넉한 타임아웃
  (`API_TIMEOUT_MS`, 기본 30초)으로 대응 중이지만 완전히 막지는 못함. 실행이
  실패하면 재시도 알림 메일이 가고, 몇 분~몇십 분 뒤 GitHub Actions에서 수동
  재실행하면 대부분 해결됨.
- **이 세션(로컬 sandbox)에서 직접 확인 불가한 것들**: `apis.data.go.kr`과
  Azure Blob Storage(아티팩트 다운로드 URL) 호스트가 이 개발 세션의 네트워크
  허용목록에 없어서, 로컬에서 실제 API 응답이나 아티팩트 파일을 직접 받아볼
  수 없음. GitHub Actions 로그(집계 수치)까지만 확인 가능 — 실제 매칭된 공고
  제목까지 보려면 사용자가 이메일이나 아티팩트를 열어봐야 함.
- **GitHub Actions workflow_dispatch를 이 세션에서 직접 트리거하는 것도 불가**
  (`403 Resource not accessible by integration`) — 수동 실행은 사용자가 직접
  Actions 탭에서 눌러야 함.

## 10. 향후 개선 아이디어 (아직 안 한 것)

- **계약 형태(설계~시공 통합 vs 설계만/시공만) 자동 판별**: 지금은 제목 텍스트로만
  판단해서 "설계공모"류만 걸러내는 수준. data.go.kr API에 발주방식을 더 명확히
  구분하는 필드가 있는지 추가 조사 여지 있음.
- **과업내용 첨부파일(HWP/PDF) 파싱**: 지금은 제목만 보는데, 첨부파일까지 열어
  키워드 매칭하면 누락을 더 줄일 수 있음 (난이도 높음 — 별도 프로젝트급).
- **테스트 커버리지**: 매칭 로직(`matchEngine`, `keywordMatcher`)은 테스트가
  탄탄하지만, config 파일의 실제 키워드 목록 자체에 대한 회귀 테스트(과거에
  걸러냈던 오탐 공고 제목들을 테스트 케이스로 고정)는 없음 — 이번 인수인계
  시점에 `test/matchEngine.test.ts`에 실제 오탐/좋은 예시 제목들을 상수로
  박아두는 회귀 테스트를 추가하면 다음에 키워드를 손댈 때 실수로 좋은 예시를
  깨뜨리는 걸 막을 수 있음.
- **자격조건 등록증 만료 확인**: `held-qualifications.json`의 `_note`에 남아있는
  만료 의심 항목(공간정보DB구축서비스, 전시회기획및대행서비스) 실제 확인 필요.
