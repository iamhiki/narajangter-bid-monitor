# 나라장터 입찰 모니터링 시스템

전시 설계/시공업체를 위한 나라장터(국가종합전자조달) 자동 입찰 모니터링 시스템입니다.
공공데이터포털(data.go.kr)의 **나라장터 입찰공고정보서비스(본공고)** 와
**나라장터 사전규격정보서비스(사전규격)** 를 매주 조회해, 세부품명코드/업종코드/키워드
기준으로 매칭되는 공고를 찾아 담당자에게 이메일로 자동 발송합니다.

## 동작 개요

1. 최근 `LOOKBACK_DAYS`일(기본 7일) 동안 게시된 공고를 본공고/사전규격 API에서
   물품·용역·공사 3개 업무구분별로 조회합니다. (지역 제한 없음, 전국 대상)
2. 각 공고에 대해 **코드 매칭**(세부품명코드/업종코드)과 **키워드 매칭**(제목)을 각각 수행합니다.
3. 코드와 키워드가 **둘 다** 매칭되면 `강력추천`, **둘 중 하나만** 매칭되면 `참고용`으로 분류합니다.
4. 본공고/사전규격을 완전히 분리된 섹션으로 나눈 리포트를 만들어 사람 검토 없이 즉시 이메일로 발송합니다.
5. 발송 성공 여부와 무관하게 `output/` 폴더에 리포트 파일(html/txt)을 남겨 데이터 유실을 방지합니다.
6. 조회/발송 도중 오류가 나면 (설정된 경우) 별도의 실패 알림 메일을 보내고, 원인 진단을 위해
   민감정보(서비스키, SMTP 비밀번호)는 로그/메일에서 자동으로 마스킹합니다.

## 매칭 대상 (설정 파일에서 관리)

| 파일 | 내용 |
|---|---|
| `config/keywords.json` | 제목 키워드 목록(`keywords`) + 제외 키워드 목록(`excludeKeywords`) + 최소 예산금액(`minBudgetAmount`). 자유롭게 추가/삭제 가능 |
| `config/codes.json` | 세부품명코드(`productCodes`, 물품 공고용) / 업종코드(`industryCodes`, 용역·공사 공고용) — **관심 분야** 매칭용 |
| `config/held-qualifications.json` | 우리 회사가 실제 보유한 등록물품/등록업종 — **입찰 참가자격 충족 여부** 판정용 (아래 "자격조건 필터" 참고) |
| `config/recipients.json` | 리포트를 받을 이메일 목록 (여러 명 추가 가능) |

코드/키워드/수신자를 바꿀 때는 코드 수정이 필요 없고, 해당 JSON 파일만 수정하면 다음 실행부터 반영됩니다.

### 제외 키워드 (`excludeKeywords`)

제목에 `excludeKeywords`의 단어가 하나라도 포함되면, 코드/키워드가 매칭되어도 **무조건 결과에서 제외**합니다.
일반 구매·대행·정비·전기공사·건축처럼 코드/업종상으로는 걸리지만 실제로는 전시 설계/시공업과
무관한 공고를 걸러내기 위한 용도입니다.

> **키워드 매칭 범위에 대한 중요한 제한사항**: data.go.kr API는 공고 "제목"과 일부 메타데이터만
> 제공하며, 상세 "과업내용"은 첨부파일(HWP/PDF)로만 제공되어 API로 가져올 수 없습니다.
> 따라서 키워드 매칭은 **공고 제목 + 품목명** 기준으로 동작합니다. 과업내용까지 훑어야 하는 공고는
> `참고용`으로 분류되지 않고 누락될 수 있으니, 완전 자동화된 필터로만 의존하지 말고 나라장터를
> 주기적으로 직접 훑어보는 것을 권장합니다.

> **키워드/제외 키워드는 공백 유무를 무시하고 매칭됩니다**: "운영 용역"으로 등록해두면
> 제목에 "운영용역"(공백 없음)으로 적혀 있어도 매칭됩니다. 두 표기를 따로 등록할 필요는 없습니다.

### 업종코드(용역·공사) 단독 매칭은 결과에 포함되지 않습니다

`codes.json`의 `industryCodes`는 공고의 "투찰가능업종명" 텍스트에 업종명이 포함되는지로
판단하는데, 이 텍스트는 무관한 공사도 참가 가능 업종 중 하나로 "실내건축공사업" 등을 폭넓게
나열해두는 경우가 많아 정밀도가 낮습니다 (예: 충전시설 구축공사, 교통신호등 설치공사, 내진보강공사
등도 업종코드만으로는 걸릴 수 있음). 그래서 업종코드는 **제목 키워드가 함께 매칭될 때만**
결과에 포함됩니다 — 업종코드만 매칭되고 키워드가 없으면 제외됩니다. 반면 세부품명번호(물품)는
정확일치라 정밀도가 높으므로 단독으로도 포함됩니다.

### 최소 예산금액 (`minBudgetAmount`)

예산금액(추정가격 등)이 확인되는 공고 중 이 금액(원) 미만인 공고는 코드/키워드가 매칭되어도
제외합니다. 값을 `null`로 두면 예산 필터를 사용하지 않습니다. 예산 정보가 API 응답에 없는
공고(`budgetAmount`가 `null`)는 판단할 수 없으므로 제외하지 않고 통과시킵니다.

## 업종코드 매칭 방식에 대한 안내

data.go.kr 입찰공고 API는 공고에 걸린 업종코드 목록을 직접 내려주지 않고, "투찰가능업종명"
텍스트만 제공합니다. 이 시스템은 그 텍스트에 `codes.json`의 업종명이 포함되는지로 매칭합니다.
따라서 업종명 표기가 API와 다르면(예: 공백/약어 차이) 매칭이 안 될 수 있습니다 — 실제 운영 중
매칭 누락이 의심되면 `output/`에 저장된 원본 리포트나 `npm run verify:api` 결과를 보고
`config/codes.json`의 name 값을 API 표기에 맞게 조정하세요.

## 자격조건 필터 (입찰참가자격 부족 공고 자동 제외)

발주처가 요구하는 참가자격(면허/업종 제한) 중 우리 회사가 보유하지 못한 항목이 **2개 이상**이면
그 공고는 강력추천/참고용 판정과 무관하게 리포트에서 제외합니다 (1개까지는 통과).

- 회사가 보유한 자격은 `config/held-qualifications.json`에 등록물품(`heldProducts`)/등록업종(`heldIndustries`)
  형태로 관리합니다 — 나라장터 "경쟁입찰참가자격등록증"을 기준으로 작성했습니다. 등록증이 갱신되면
  (특히 업종 추가/제조물품 추가, 유효기간 만료 등) 이 파일도 함께 갱신해주세요.
- 공고별 참가자격은 data.go.kr의 `getBidPblancListInfoLicenseLimit`(면허제한정보조회) API로 조회합니다.
  발주처가 정한 "제한그룹"이 하나의 자격조건 단위이며, 그룹 안에 여러 업종이 나열되어 있으면
  그 중 하나만 보유해도 그 조건은 충족된 것으로 판단합니다(OR). 충족하지 못한 그룹 수가 2개 이상이면 제외합니다.
- **적용 범위**: 이 필터는 **본공고에만** 적용됩니다. 사전규격은 아직 정식 공고 전 단계라 참가자격
  정보 자체가 없어(대응 API 없음) 필터 대상이 아니며 그대로 통과합니다.
- **실패 시 안전 정책(fail-open)**: 자격조건 조회 자체가 실패하거나 특정 공고의 자격조건 정보가
  없으면, 걸러내지 않고 그대로 통과시킵니다. API 오류 때문에 정상 후보가 조용히 사라지는 것을 막기 위함입니다.
- **조회 방식**: `getBidPblancListInfoLicenseLimit`는 `bidNtceNo`를 넘겨도 서버가 필터링해주지
  않고 조회기간 내 전체 데이터를 페이지 단위로 내려줍니다(2026-07-28 실측 확인). 그래서 공고
  1건씩 호출하는 대신, 조회기간 전체를 **한 번만** 페이지네이션으로 받아 공고번호별로 로컬에서
  묶은 뒤 조회합니다 — 매칭 건수가 많아져도 API 호출 횟수가 늘지 않습니다.
- 이 API의 실제 필드명은 `lmtGrpNo`(제한그룹번호), `permsnIndstrytyList`(허용업종목록)로 확인되어
  `src/api/fieldCandidates.ts`의 `LICENSE_LIMIT_FIELD_CANDIDATES`에 최우선 후보로 반영해뒀습니다.
  `npm run verify:api` 실행 시 마지막에 이 API도 함께 테스트하니, 응답이 이상하면 그 출력을 보고
  필드 후보를 조정하세요.

## 사전 준비

### 0. Node.js 설치

이 프로젝트는 Node.js 20 이상이 필요합니다 (`package.json`의 `engines.node` 참고).

```bash
node -v   # v20.x 이상인지 확인
```

설치되어 있지 않다면 [nodejs.org](https://nodejs.org/)에서 LTS 버전을 받거나,
Windows에서는 winget으로 설치할 수 있습니다.

```powershell
winget install -e --id OpenJS.NodeJS.LTS
```

설치 직후에는 새 터미널을 열어야 `node`/`npm` 명령이 인식됩니다.

### 1. data.go.kr API 신청

아래 두 서비스를 각각 **활용신청** 하세요 (승인까지 최대 1~2일 소요될 수 있습니다).

- [조달청_나라장터 입찰공고정보서비스](https://www.data.go.kr/data/15129394/openapi.do)
- [조달청_나라장터 사전규격정보서비스](https://www.data.go.kr/data/15129437/openapi.do)

승인 후 마이페이지 > 개발계정 상세보기에서 발급되는 인증키 중 반드시
**"일반 인증키(Decoding / 평문)"** 값을 `.env`의 `NARA_BID_SERVICE_KEY`에 넣으세요.
("Encoding" 키를 넣으면 URL 인코딩이 중복 적용되어 인증 오류가 발생합니다.)

두 서비스 인증키가 동일하다면 `NARA_PRESTD_SERVICE_KEY`는 비워둬도 됩니다(자동으로 재사용).

### 2. SMTP 발신 계정

Gmail을 쓴다면 [앱 비밀번호](https://myaccount.google.com/apppasswords)를 발급받아
`SMTP_PASS`에 넣으세요 (일반 로그인 비밀번호는 동작하지 않습니다). 회사 메일 서버가 있다면
해당 SMTP 정보를 사용하면 됩니다.

### 3. 환경변수 설정

```bash
cp .env.example .env
# .env를 열어 API 키 / SMTP 정보를 채워넣기
```

## 사용 패키지

`npm install` 한 번으로 아래 패키지가 모두 설치됩니다 (버전은 `package.json` 참고).

| 패키지 | 용도 |
|---|---|
| `dotenv` | `.env` 파일의 환경변수 로드 |
| `fast-xml-parser` | data.go.kr API의 XML 응답 파싱 |
| `nodemailer` | SMTP로 리포트/실패 알림 이메일 발송 |
| `zod` | 환경변수·설정 파일(config/*.json) 형식 검증 |
| `typescript` / `tsx` (dev) | TypeScript 컴파일 및 스크립트 직접 실행 |
| `vitest` (dev) | 단위 테스트 실행 |
| `@types/node`, `@types/nodemailer` (dev) | TypeScript 타입 정의 |

## 로컬 실행

```bash
npm install

# API/SMTP 없이 매칭 로직과 리포트만 확인하고 싶다면:
npm run report:dry-run

# 실제 API 키를 받은 직후, 응답 필드명이 예상과 맞는지 진단:
npm run verify:api

# 실제 조회 + 이메일 발송:
npm run report

# 테스트 / 타입체크
npm test
npm run typecheck
```

`npm run verify:api`는 6개 오퍼레이션(본공고·사전규격 × 물품·용역·공사)을 소량으로 호출해
원본 응답 필드명을 그대로 출력합니다. 만약 리포트에 제목/예산 등이 "미상"으로 자주 나온다면,
이 스크립트 결과를 보고 `src/api/fieldCandidates.ts`에 실제 필드명을 후보로 추가하세요.
(data.go.kr이 API 스키마를 개정하며 필드명이 바뀌는 경우가 종종 있어, 코드 로직을 건드리지 않고
후보 목록만 수정하면 되도록 설계했습니다.)

## 매주 월요일 자동 발송 (GitHub Actions)

저장소 루트의 `.github/workflows/weekly-bid-report.yml`이 매주 월요일 07:00(KST)에
자동으로 실행되도록 설정되어 있습니다.

> **왜 로컬 `.env`와 별개로 등록해야 하나요?**
> 이 자동 실행은 내 컴퓨터가 아니라 GitHub의 서버에서 돌아갑니다. `.env` 파일은
> `.gitignore`에 포함되어 있어 저장소에 올라가지 않으므로(API 키 유출 방지), GitHub
> 서버는 로컬 `.env` 값을 전혀 볼 수 없습니다. 그래서 동일한 값을 저장소 설정의
> "Secrets"라는 별도 저장 공간에 **한 번 더** 등록해야 워크플로가 이 값을 읽을 수
> 있습니다. 등록하지 않으면 실행 시 값이 빈 문자열이 되어 환경변수 검증 단계에서
> 바로 실패합니다.

등록 절차: 저장소 페이지 → **Settings** → **Secrets and variables → Actions** →
**New repository secret** → 아래 이름으로 로컬 `.env`와 동일한 값을 하나씩 등록.

| Secret 이름 | 설명 |
|---|---|
| `NARA_BID_SERVICE_KEY` | 입찰공고정보서비스 인증키 (Decoding) |
| `NARA_PRESTD_SERVICE_KEY` | 사전규격정보서비스 인증키 (없으면 위 키와 동일하게 등록) |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` | SMTP 서버 정보 |
| `SMTP_USER` / `SMTP_PASS` | SMTP 로그인 계정 |
| `SMTP_FROM` | 발신자 표시 (예: `나라장터 입찰 모니터링 <noreply@example.com>`) |

Actions 탭에서 `workflow_dispatch`로 수동 실행도 가능하며, `dry_run` 입력을 `true`로 주면
이메일 없이 리포트 파일만 생성해 확인할 수 있습니다.

GitHub Actions 대신 자체 서버의 crontab/PM2로 운영하고 싶다면, 서버에 `.env`를 두고
`npm run report`를 매주 월요일 아침에 실행하도록 등록하면 동일하게 동작합니다.

## 오류 처리 정책

- **API 호출 실패**: 네트워크 오류/타임아웃/일시적 오류(HTTP 5xx, TPS 초과 등)는 지수 백오프로
  자동 재시도합니다(`API_MAX_RETRIES`, 기본 3회). 인증키 오류처럼 재시도해도 해결되지 않는
  오류는 즉시 실패 처리됩니다.
- **부분 실패 허용**: 물품/용역/공사 6개 조회 중 일부만 실패하면, 성공한 나머지 데이터로
  리포트를 발송하되 어떤 업무구분 조회가 실패했는지 리포트 상단에 경고로 표시합니다
  (실행 종료 코드도 2로 구분되어 CI에서 구분 가능).
- **전체 실패**: 6개 조회가 모두 실패하면(예: API 전면 장애, 인증키 만료) "매칭 0건" 리포트를
  보내는 대신 발송을 중단하고 실패 알림 메일을 보냅니다 — 실제로는 장애 상황인데
  "이번 주 해당 없음"으로 오인하는 것을 방지하기 위함입니다.
- **이메일 발송 실패**: 재시도 후에도 실패하면 로그에 오류를 남기고, 계산된 리포트는
  `output/`에 파일로 보존됩니다 (GitHub Actions에서는 아티팩트로도 업로드됩니다).
- **민감정보 보호**: API 서비스키/SMTP 비밀번호는 오류 로그나 실패 알림 메일에 절대
  그대로 노출되지 않도록 마스킹 처리됩니다.
- **설정 검증**: 환경변수와 `config/*.json`은 실행 시작 시점에 형식/이메일 유효성/중복
  여부를 검증하며, 문제가 있으면 무엇이 잘못됐는지 구체적으로 알려주고 즉시 중단합니다.

## 신뢰도(강력추천/참고용)에 대한 주의

이 시스템의 매칭은 API가 제공하는 메타데이터(제목, 세부품명코드, 투찰가능업종명)만을 근거로
하는 **1차 스크리닝**입니다. `강력추천`이어도 반드시 원문 공고와 첨부 규격서를 확인한 뒤
입찰 참가 여부를 결정하세요. (리포트 하단에도 동일한 안내 문구가 포함되어 있습니다.)

## 핵심 로직 위치 (팀원용 빠른 참조)

"이 기능이 어디 코드에 있지?"를 찾을 때 쓰는 표입니다.

| 기능 | 위치 |
|---|---|
| **강력추천/참고용 판정** | `src/matching/matchEngine.ts`의 `evaluateNotice()` — 코드 매칭과 키워드 매칭이 **둘 다** 되면 강력추천, 하나만 되면 참고용 |
| 강력추천/참고용 타입 정의 | `src/matching/types.ts` (`Confidence` 타입) |
| 키워드/제외키워드 매칭 | `src/matching/keywordMatcher.ts` |
| 세부품명코드/업종코드 매칭 | `src/matching/codeMatcher.ts` |
| 최소 예산금액 필터 | `src/matching/matchEngine.ts`의 `evaluateNotice()` 앞부분 (`config.minBudgetAmount`) |
| 자격조건(참가자격 부족) 필터 | `src/matching/qualificationFilter.ts`, `src/matching/applyQualificationFilter.ts` |
| 리포트에서 강력추천/참고용 배지 렌더링 | `src/report/buildReport.ts` (`CONFIDENCE_STYLE`) |
| 환경변수 로드/검증 | `src/config/env.ts` |
| `config/*.json` 로드/검증 | `src/config/loadJsonConfig.ts` |
| data.go.kr API 응답 필드명 후보 | `src/api/fieldCandidates.ts` |
| 공동수급(공동이행/분담이행) 허용 여부 조회 | `src/api/jointBidApi.ts` — g2b.go.kr 비공식 API, **표시 전용**(필터·등급에 영향 없음), 본공고만 해당 |
| 이메일 발송 (리포트/실패 알림) | `src/email/sendReportEmail.ts`, `src/email/mailer.ts` |
| 전체 실행 순서 | `src/index.ts` |

수정하면 됩니다 (위 "매칭 대상" 섹션 참고).
